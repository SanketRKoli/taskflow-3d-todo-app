SECTION 1 — HOW THE APP WORKS (Big Picture)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

FLOW:
  1. User opens index.html (login page)
  2. User signs up → account saved in localStorage
  3. User signs in → session saved in sessionStorage
  4. Browser redirects to app.html
  5. app.html checks sessionStorage for session
  6. If no session found → redirect back to index.html
  7. User manages tasks → all saved in localStorage
  8. User clicks "Sign Out" → sessionStorage cleared → back to login
  9. When user CLOSES the browser tab → sessionStorage auto-clears
  10. Next visit → must log in again (that's the "one-time login" behavior)

STORAGE USED:
  localStorage  → permanent across sessions:
    tf_users                = { username: { name, password } }
    tf_tasks_{username}     = [ task1, task2, ... ]
    tf_theme                = "dark" or "light"

  sessionStorage → cleared when tab closes:
    tf_session = { username, name }

index.html
  The first page users see.
  Contains TWO forms inside one page:
    - Signup form (shown by default)
    - Login form (shown after clicking "Sign In" tab)
  The tab switcher shows/hides forms using CSS class "hidden".
  A sliding indicator div (.tab-slider) slides left/right for visual effect.
  Floating emoji particles are generated by JS in the background.
  The left "brand panel" shows the logo, headline, feature pills,
  and three floating demo task card previews.
  The right "auth panel" contains the actual forms.

app.html
  The main dashboard. Requires session to access.
  Key sections:
    - Topbar: logo, stats pills, greeting, theme toggle, logout
    - Input zone: task text input + priority select + due date picker
    - Filter nav: All / Pending / Done / High Priority + search box
    - Hint bar: keyboard shortcut reminders
    - Task list: where all task cards are rendered
    - Grass template: hidden <template> element cloned for done tasks
    - Edit modal: popup dialog for editing a task

css/login.css
  Styles for the login page.
  Key design decisions:
    - Two-column grid layout (brand left, auth right)
    - Animated grid overlay using background-size CSS
    - Floating particles animated via @keyframes floatUp
    - Glassmorphism card effect (backdrop-filter blur)
    - Righteous font for headings (fun, display-style)
    - Nunito font for body text (friendly, readable)
    - Demo cards animate with @keyframes demoFloat
    - Feature pills animate in with staggered delays

SECTION 3 — js/login.js EXPLAINED
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

STEP 1 — Session Guard (runs immediately on load):
  Checks sessionStorage for "tf_session".
  If found → user is already logged in → redirect to app.html.
  This prevents showing the login page to a logged-in user.

STEP 2 — Spawn Particles:
  Creates 18 random <span> elements with emoji inside .bg-particles div.
  Each gets a random: left position, font-size, animation-duration, delay.
  CSS @keyframes floatUp moves them from bottom to top of screen.
  This gives the fun floating background effect on the login page.

FUNCTION: switchTab(tab)
  Controls which form is visible.
  Adds/removes CSS class "hidden" on form sections.
  Adds/removes CSS class "active" on tab buttons.
  Toggles CSS class "right" on the slider div.
    "right" class applies: transform: translateX(100%) in CSS
    This slides the highlight from left tab to right tab.

FUNCTION: toggleEye(inputId, btn)
  Changes password input type between "password" and "text".
  Updates button emoji between 👁 and 🙈.

PASSWORD STRENGTH METER:
  Listens to "input" event on the password field.
  Calculates score 0-4 based on:
    - Length >= 4 characters   → +1
    - Length >= 8 characters   → +1
    - Has uppercase letter     → +1
    - Has a number             → +1
    - Has a special character  → +1
  Updates .strength-bar width and color.
  Updates .strength-txt label (Weak / Fair / Good / Strong 💪).

FUNCTION: getUsers()
  Reads "tf_users" from localStorage and parses JSON.
  Returns object: { username: { name, password }, ... }
  Falls back to {} if nothing stored or JSON parse fails.

FUNCTION: handleSignup(event)
  Prevents form default submission.
  Reads: name, username (lowercased), password.
  Validates:
    - name is not empty
    - username is not empty
    - username >= 3 characters
    - username only contains letters, numbers, underscore (regex)
    - password >= 4 characters
    - username not already taken (checks getUsers())
  If valid: saves user to localStorage, shows success, auto-switches to login.
  Uses setMsg() to display colored feedback messages.

FUNCTION: handleLogin(event)
  Prevents form default submission.
  Reads: username (lowercased), password.
  Validates: username and password not empty.
  Looks up username in getUsers().
  If not found: error message.
  If password doesn't match: error message.
  If valid: saves session to sessionStorage, redirects to app.html.

SESSION OBJECT stored in sessionStorage:
  { username: "alex123", name: "Alex Johnson" }
  sessionStorage clears automatically when browser tab is closed.
  This forces the user to log in again on every new tab/visit.

ENTER KEY SUPPORT:
  Listens to document keydown event.
  If Enter is pressed: finds the currently visible form and submits it.

SECTION 4 — js/app.js EXPLAINED
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. AUTH GUARD:
   Reads sessionStorage "tf_session" immediately.
   If null → user not logged in → redirects to index.html.
   Parses the session JSON to get { username, name }.
   STORAGE_KEY = "tf_tasks_alex123" (unique per user).

2. THEME:
   applyTheme(t): sets data-theme attribute on <html> element.
   CSS picks this up and swaps all CSS variables automatically.
   Saves preference to localStorage so it persists across sessions.

3. STATE VARIABLES:
   tasks[]     → array of task objects in memory
   selectedId  → id of currently selected task (or null)
   filterMode  → current filter: "all" | "pending" | "done" | "high"
   editingId   → id of task being edited in the modal (or null)
   bombTimers  → object: { taskId: { remaining, interval, cancelled } }

4. TASK OBJECT STRUCTURE:
   {
     id:        "lf3k2abc",     string (unique, auto-generated)
     text:      "Buy groceries", string
     done:      false,           boolean
     priority:  "high",          "high" | "normal" | "low"
     due:       "2025-06-15",    string (YYYY-MM-DD) or ""
     createdAt: 1716000000000,   number (Date.now())
   }

5. loadTasks() / saveTasks():
   Reads/writes tasks array to localStorage under STORAGE_KEY.
   Each user has their own storage key, so data never mixes.

6. renderTasks():
   Core UI update function. Called whenever state changes.
   Steps:
     a. updateStats() → update the 4 counter pills in topbar
     b. getFiltered() → apply filter + search
     c. Sort: pending tasks first, done tasks last
     d. If empty → show empty-state div
     e. Otherwise: clear #taskList, loop, call buildCard(), append

7. buildCard(task, idx):
   Creates a <div class="task-card"> element.
   Sets classes: "done" if task.done, "selected" if task.id === selectedId.
   Sets data-pri attribute → CSS uses this for the left color stripe.
   Sets animationDelay → staggered entry (idx * 0.045 seconds).
   Dot gradient: green checkmark if done, colored gradient if pending.
   Generates HTML innerHTML with: dot, body (text + meta badges), actions.
   If task.done → calls attachGrass(card) to add grass overlay.
   If bomb is ticking → restores bomb overlay on re-render.
   Attaches 4 event listeners: card click (select), ✔, ✏️, 🗑.

8. toggleSelect(id, card):
   If same task clicked again → deselect.
   Otherwise → remove "selected" from all cards, add to clicked card.
   Updates selectedId variable.

9. toggleDone(id):
   Finds task in array, flips task.done boolean.
   Saves + re-renders. Re-render creates/removes grass overlay.

10. attachGrass(card):
    Clones the <template id="grassTpl"> element (deep clone).
    Appends it inside the task card.
    Template contains: sun, ground, 8 blade spans, 2 flowers, label.
    CSS animates: blade growth (scaleY 0→1), sway, flower pop, sun bob,
    and the whole overlay clips in from bottom with clip-path animation.

11. addTask(text):
    Creates task object with uid() ID and current values.
    Pushes to front of tasks array (unshift).
    Saves and re-renders.
    The CSS @keyframes spinIn handles the 3D entry animation.

12. openEdit(task) / saveEdit() / closeModal():
    openEdit: fills modal form fields with task data, shows modal.
    saveEdit: validates, updates task in array, saves, re-renders, closes.
    closeModal: adds "hidden" class back to modal backdrop.
    Backdrop click and Escape key also close the modal.

13. BOMB SYSTEM — startBomb(id, card):
    Creates timer entry: bombTimers[id] = { remaining:5, interval, cancelled }.
    Calls attachBombOverlay(card, id) to show the bomb UI.
    Sets up setInterval (every 1 second):
      - Decrements remaining
      - Updates the .bomb-num element on screen
      - If reaches 0: clear interval, call triggerBlast(id)
      - If cancelled: clear interval, re-render

    attachBombOverlay(card, id):
      Creates a div.bomb-overlay covering the whole card.
      Contains: 💣 emoji (shake animation), countdown number (pulse animation), hint text.
      Click listener on the overlay calls cancelBomb(id).

    cancelBomb(id):
      Clears the interval, marks as cancelled, deletes timer entry.
      Re-renders to remove the bomb overlay.

14. BLAST EFFECT — triggerBlast(id):
    Gets card's screen position via getBoundingClientRect().
    cx, cy = center of the card on screen.
    Adds "blasting" class to card → CSS shrink+fade animation.
    Calls launchParticles(cx, cy) with center coordinates.
    After 350ms delay: removes task from array, saves, re-renders.

    launchParticles(ox, oy):
      Creates 70 particle objects, each with:
        x, y     → start at explosion center
        vx, vy   → velocity (random angle and speed)
        r        → radius (2.5 to 8 pixels)
        color    → random from 9 colors
        alpha    → starts at 1, decreases to 0
        rot, rotV → rotation and rotation velocity
        isRect   → half are circles, half are rectangles
      requestAnimationFrame loop:
        Each frame: apply physics (gravity +0.38, friction vx*0.97)
        Decrease alpha by 0.020 per frame (~50 frames visible)
        Draw with shadowBlur for glow effect
        Stop when all particles have alpha <= 0

    Physics explanation:
      p.vy += 0.38  → gravity pulls particles down each frame
      p.vx *= 0.97  → air resistance slows horizontal movement
      The combination creates realistic parabolic arc paths.

15. Canvas sizing:
    Canvas is fixed position, full screen, pointer-events:none.
    Resized on window resize event.
    Cleared after all particles fade out.

SECTION 5 — CSS TRICKS EXPLAINED
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

CSS VARIABLES (Custom Properties):
  :root { --accent: #a78bfa; }                  ← defined once
  [data-theme="light"] { --accent: #7c3aed; }   ← overridden for light
  When JS does: html.setAttribute('data-theme','light')
  Every element using var(--accent) instantly updates. Zero JS style changes.

CSS CLIP-PATH ANIMATION (grass reveal):
  from { clip-path: inset(100% 0 0 0); }   ← hides everything (clips from top)
  to   { clip-path: inset(0% 0 0 0); }     ← reveals fully
  Creates a bottom-to-top "wipe" reveal effect.

CSS ::BEFORE PSEUDO-ELEMENT (priority stripe):
  .task-card::before {
    content: '';
    position: absolute;
    left: 0; top: 0; bottom: 0;
    width: 3.5px;
  }
  .task-card[data-pri="high"]::before { background: var(--red); }
  No extra HTML needed. The color changes by reading the data attribute.

CSS PERSPECTIVE / 3D SPIN:
  @keyframes spinIn {
    0%   { transform: rotateY(90deg) scale(.8); }
    60%  { transform: rotateY(-10deg) scale(1.03); }
    100% { transform: none; }
  }
  The 60% keyframe overshoots slightly, creating a bounce/settle effect.
  This makes the card feel like it's snapping into place.

GLASSMORPHISM:
  background: rgba(255,255,255,.04);
  backdrop-filter: blur(8px);
  border: 1.5px solid rgba(255,255,255,.08);
  The blur on backdrop-filter blurs whatever is behind the element.
  Gives the "frosted glass" look. Requires Chrome 76+.

ANIMATION STAGGER:
  card.style.animationDelay = `${idx * 0.045}s`;
  Each card gets a slightly longer delay based on its position.
  Cards 0, 1, 2, 3... appear at 0ms, 45ms, 90ms, 135ms...
  Creates a cascading entrance effect.

GRADIENT TEXT:
  background: linear-gradient(135deg, #e8e0ff, #a78bfa, #f472b6);
  -webkit-background-clip: text;
  -webkit-text-fill-color: transparent;
  The gradient is set as the background, then clipped to the text shape.
  Text fill becomes transparent so the gradient shows through.

SECTION 6 — JAVASCRIPT CONCEPTS USED
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

IIFE (Immediately Invoked Function Expression):
  (function sessionGuard() { ... })();
  Runs once immediately when the script loads.
  Used for the auth check so it runs before anything else.

sessionStorage vs localStorage:
  sessionStorage: data exists only while the browser tab is open
  localStorage:   data persists across browser closes and restarts

Array methods:
  tasks.unshift(task)        → add to start of array
  tasks.filter(t => !t.done) → returns new array of pending tasks
  tasks.find(t => t.id===id) → returns first matching task
  tasks.filter(t => t.id!==id) → returns array without that task

Template literals (backtick strings):
  `Hello ${name}` → embeds variable into string
  Used for innerHTML strings (building card HTML dynamically)

DOM API methods:
  document.createElement('div')         → creates element
  element.classList.add/remove/toggle   → CSS class manipulation
  element.dataset.id = task.id          → sets data-id attribute
  element.addEventListener(event, fn)   → attach event handler
  element.getBoundingClientRect()       → get screen position
  element.querySelector('.class')       → find child element
  element.appendChild(child)            → add child to element
  document.getElementById('taskTpl')    → get element by id
  element.content.cloneNode(true)       → deep-clone a <template>

Canvas API:
  canvas.getContext('2d')               → 2D drawing context
  ctx.clearRect(0, 0, w, h)            → erase canvas
  ctx.save() / ctx.restore()           → save/restore drawing state
  ctx.globalAlpha                       → transparency (0-1)
  ctx.translate(x, y)                  → move coordinate origin
  ctx.rotate(angle)                    → rotate drawing axis
  ctx.fillStyle = color                → set fill color
  ctx.shadowBlur = 7                   → set glow effect
  ctx.arc(0, 0, r, 0, Math.PI*2)       → draw circle path
  ctx.fillRect(-r, -r/2, r*2, r)       → draw rectangle
  ctx.fill()                           → fill the current path
  requestAnimationFrame(fn)            → call fn before next frame (~60fps)
  cancelAnimationFrame(id)             → stop the animation loop

setInterval / clearInterval:
  id = setInterval(fn, 1000)  → call fn every 1000ms
  clearInterval(id)           → stop it
  Used for bomb countdown.

Math.random() tricks:
  Math.random() * Math.PI * 2       → random angle (0 to 2π radians)
  Math.cos(angle) * speed           → x velocity from angle
  Math.sin(angle) * speed           → y velocity from angle
  This distributes particles in all directions from center.

SECTION 7 — COMMON ERRORS & FIXES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PROBLEM: Redirected back to login even after signing in
FIX: You're opening app.html directly. sessionStorage only exists
     in the same tab. Always start from index.html.

PROBLEM: "Login works but I can't see tasks on reload"
FIX: That's by design! sessionStorage clears on tab close.
     Sign in again — your tasks are still saved in localStorage.

PROBLEM: backdrop-filter blur not working (glass effect missing)
FIX: This requires a Chromium-based browser or Safari.
     Firefox needs a flag enabled. IE/old Edge: not supported.

PROBLEM: Grass animation not showing on completed tasks
FIX: Make sure the <template id="grassTpl"> exists in app.html.
     Check browser console for errors.

PROBLEM: Canvas particles not visible
FIX: Make sure #blastCanvas has position:fixed and z-index:9999.
     Check that canvas.width/height are being set (not 0).

PROBLEM: Page looks broken when opening as file://
FIX: Use a local server. Try: npx serve . or python -m http.server 5500

PROBLEM: Signup says "Username taken" when it shouldn't
FIX: All usernames are lowercased before storage.
     "Alex123" and "alex123" are the same username.
